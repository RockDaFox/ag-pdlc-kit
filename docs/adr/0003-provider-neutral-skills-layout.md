# ADR-0003 — One provider-neutral `skills/` tree, one manifest pair per host

| | |
|---|---|
| **Status** | Accepted |
| **Date** | 2026-09-14 |
| **Supersedes** | [ADR-0001](0001-distribution-as-claude-code-plugin.md) |

## Context

[ADR-0001](0001-distribution-as-claude-code-plugin.md) assumed a single host,
Claude Code, and shaped the repository around its marketplace: the plugin in
`plugins/croakness/`, bundled files reached through `${CLAUDE_PLUGIN_ROOT}`.
Croakness now has to serve GitHub Copilot as well.

Four things observed on this machine settle the shape of the answer:

- GitHub Copilot has its own plugin marketplace. `~/.copilot/config.json`
  lists installed plugins with their marketplace and a source hash, and each
  one is cloned whole into `~/.copilot/installed-plugins/`. The manifest pair
  it reads lives at `.github/plugin/`.
- Both hosts read the same `SKILL.md` format — name and description in
  frontmatter, one directory per skill under `skills/`. There is also a
  vendor-neutral `~/.agents/` tree holding third-party skills in exactly that
  format.
- Skills distributed this way reference their bundled files by paths relative
  to the skill directory (`references/foo.md`), never through a host-specific
  variable.
- A marketplace entry may source the repository root (`"source": "./"`),
  which ADR-0001 rejected only for lack of evidence.

So the content is already portable. Only the packaging differs.

## Decision

The repository root is the plugin. The canonical content is `skills/` at the
root: one directory per skill, plus `skills/_croakness-shared/` holding the
discipline reference and the templates. Nothing in it is host-specific —
bundled files are reached by paths relative to the skill's own directory, and
no host-provided variable is used.

Each host gets a manifest pair pointing at that same tree, and nothing else:

- **Claude Code** — `.claude-plugin/marketplace.json` and `plugin.json`.
- **GitHub Copilot** — `.github/plugin/marketplace.json` and `plugin.json`.

Both source `"./"` and declare `skills/`. Adding a host means adding a
manifest, never a copy of the content.

## Alternatives weighed

- **Full per-provider copies regenerated by a sync script** (the model used by
  at least one widely distributed plugin) — rejected twice over: it puts
  executable code in a repository whose whole argument is that it has none,
  and it duplicates the workflow text, which the stated-once rule forbids
  everywhere else in this product.
- **Self-contained Copilot prompt files under `.github/prompts/`** restating
  the workflow — rejected: two copies of the same instructions in this
  repository, certain to drift. This was the design until Copilot's
  marketplace was found, and it is the reason to look before designing.
- **Vendoring a `.croakness/` directory into every target repository** —
  rejected: it pins a vintage per project, which is the failure ADR-0001
  existed to avoid, and both hosts install globally.
- **Keeping `${CLAUDE_PLUGIN_ROOT}`** and translating it per host — rejected:
  skill-relative paths already work everywhere, and are what comparable
  skills actually use.

## Consequences

- The plugin root is the repository root, so this repository's own `AGENTS.md`
  and `docs/` ship with it. Acceptable, and useful: an installed Croakness
  carries a worked example of the format it asks for.
- Three manifests now carry the name and two carry the version. A release
  means bumping both; nothing enforces it.
- `skills/_croakness-shared/` is reached by relative path from each skill. Any
  future host that flattens skill directories, or loads a `SKILL.md` without
  its surrounding folder, breaks every link into it — silently.
- Only Claude Code and Copilot are claimed. Other hosts reading `~/.agents/`
  will probably work; none has been tested, and the README says so rather
  than implying support.
